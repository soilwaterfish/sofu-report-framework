Workflow Guide

Build, run, inspect

This page is a quick reference for the `Makefile` commands so it is easier to separate raw ingest, database refresh, percentile refresh, and static-site issues while iterating.

Normal path Fast daily run Use Docker for the real workflow run, but keep the cron path focused on ingest, daily stats, indices, and site export.
Debug path DB and site split Use the local helpers when you need to inspect the SQLite DB or rebuild just the static export from an already-updated database.
Main idea One stage at a time Separate ingest, daily stats, percentiles, and website export so each layer can be verified on its own.

Commands

Makefile reference

Command High-level purpose When to use it
make docker-build Builds the sofureport-job Docker image only. Use after changing the Dockerfile, package dependencies, or anything container-specific.
make docker-run Runs the default Docker workflow path. Use when you want the normal scheduled-style run: ingest, daily stats, computed indices, and static-site build. Percentiles are skipped by default.
make docker-run-build Builds the image and then runs the full workflow. Use when you changed code and want to be sure the run is using a fresh container image.
make docker-run-no-site Runs the default DB workflow but skips the static-site build. Use when you want to check whether ingest, daily stats, and computed indices are working without mixing in frontend/export behavior.
make docker-run-ingest Runs only the raw API ingest and SQLite merge steps. Use when you want the fastest possible check that APIs are returning data and the database is accepting new rows. By default this uses recent windows for Synoptic and FEMS, while Zentra still repairs missing water-year windows.
make docker-run-daily Runs the fast daily DB path and skips the site build. Use when you want to refresh raw data, daily stats, and computed indices without paying the percentile cost.
make docker-run-percentiles Runs only the percentile refresh against the current daily stats tables. Use for occasional heavy refreshes after the raw data and daily stats are already in good shape.
make docker-run-full Runs ingest, daily stats, computed indices, percentiles, and static-site build. Use when you explicitly want the heavyweight everything-refresh path.
make docker-run-backfill Runs a water-year repair pass for the raw APIs without rebuilding the site. Use when cron was down or you suspect a larger gap in Synoptic/FEMS/Zentra raw data and want to refill it before rebuilding anything else.
make docker-up-web Starts the nginx web service. Use when you want to serve whatever is currently in output/ locally.
make docker-down-web Stops the nginx web service. Use when you are done serving the local static site or want to reset the web layer.
make build-site-local Runs build_static_site.R on the host using the current local DB. Use when the DB looks correct and you want to test whether the website export is stale or misbuilt.
make db-qc Runs the SQLite QA/QC checks. Use when you want a pass/fail validation of required tables, duplicates, station lookup integrity, and freshness.
make db-inspect Prints a human-readable snapshot of the current DB state. Use when you want to see latest timestamps, sample labels, and flagged stale stations before rebuilding anything else.

Workflow patterns

Recommended sequences

Daily cron-style run 
make docker-build
make docker-run
make docker-up-web

This is the best normal path now. It keeps the environment aligned with the deployed workflow while avoiding the percentile refresh on every run.

Current defaults: Synoptic fetches the last 3 days, FEMS fetches the last 7 days, daily stats refresh only the last 14 days, and percentile refresh is off in the daily path.

Fast API-to-DB check 
make docker-run-ingest
make db-inspect
make db-qc

Use this when you suspect the workflow is not writing the right raw data into data/sofu.sqlite and you do not want stats or percentiles obscuring the issue.

Recover a missed window after downtime 
make docker-run-backfill
make db-inspect
make build-site-local

Use this when you had a cron interruption or another outage and need a heavier raw-data repair pass before rebuilding the site.

Refresh daily DB products without percentiles 
make docker-run-daily
make db-inspect
make db-qc

Use this when the APIs look healthy and you want the fast operational path: raw ingest, daily min/max/mean tables, and computed indices.

Run percentiles on their own cadence 
make docker-run-percentiles
make build-site-local
make docker-up-web

Use this when you want to refresh the heavy percentile tables separately, for example seasonally or after a larger backfill.

Rebuild just the website export 
make build-site-local
make docker-up-web

Use this when the DB looks current but the website appears stale. This isolates the static-site layer from the workflow layer.

Fast debugging mental model 
1. Are the APIs ingesting into SQLite?
2. Are daily stats and computed indices current?
3. Do percentiles need a separate refresh?
4. Does the static export reflect the DB?
5. Is nginx serving the latest output?

If you answer those in order, most issues get narrowed down quickly instead of bleeding across multiple layers.

Layer map

What each command touches

  • docker-run-ingest is about API calls and raw table merges only.
  • docker-run, docker-run-daily, and docker-run-no-site are about the fast operational DB path.
  • docker-run-percentiles and docker-run-full are the heavyweight refresh commands.
  • db-inspect and db-qc are about the SQLite database only.
  • build-site-local is about turning the current DB into static JSON/HTML for the website.
  • docker-up-web and docker-down-web are only about serving the already-generated files.
